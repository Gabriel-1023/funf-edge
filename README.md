# FUNF 边控台 — 吮吸玩具 × 灵猫气压

把 FUNF / SOSEXY 蓝牙玩具和 DG-LAB 的**灵猫（BMTR_1）气压传感器**接在一起，做
**边控（edging）**：气压一到阈值，玩具的全部输出立刻停掉。

```text
   灵猫 ──BLE──► DG-LAB 4 APP ──ws──► 中继 ──ws──► 本程序
                                                      │
                                            气压 ≥ 阈值 ─┤
                                                      ▼
                                             全停帧 ──BLE──► 吮吸玩具
```

---

## 1. 两个协议是怎么拼起来的

### 玩具侧（来自 `funf_ble/`，原样继承）

BLE 服务 `0000ee01`，写 `0000ee03` / 通知 `0000ee02`。下发帧固定头 `010100`：

```text
010100 <条数 N> [ attr(4) 11 val(2) ] × N
```

| attr | 含义 | 取值 |
|---|---|---|
| `0001` | 震动强度 | 0–100 |
| `0002` | 震动模式 | 1–4 |
| `0003` | 微电流强度 | 0–100 |
| `0004` | 电流模式 | 1–4 |
| `0005` | 电量 | R |
| `0007` | 吮吸强度 | 0–100 |
| `0008` | 吮吸模式 | 1–4 |
| `0009` / `000B` | 失控时长 / 功能位掩码 | bit0 震动、bit1 吮吸、bit2 电流 |
| `000D` | 呼吸灯 | 0/1 |

全停帧 `010100 03000111000003110000071100` —— 三路强度一次归零，这是边控的
执行手段。

### 灵猫侧（来自 `dungeonlab-open/dglab-websocket-server` 的 V4 协议）

灵猫**不是**一个独立开 socket 的设备。它是挂在 DG-LAB 4 APP 上的一个**设备插槽**，
气压值只能通过 APP 的中继通道拿到：

```text
DG-LAB 4 APP ──ws──► 中继（V4）──ws──► 控制方（本程序）
```

关键帧：

```jsonc
// 1. 控制方连上，拿到自己的配对 ID
{ "type": "hello", "clientId": "<我>" }

// 2. APP 用 tid=<我> 接入
{ "type": "client_attached", "clientId": "<APP>" }

// 3. APP 推全量设备表（灵猫 type == "BMTR_1"）
{ "type": "message", "clientId": "<APP>", "data": {
    "t": "ev", "ev": "devices.snapshot",
    "devices": [{ "slotId": "s1", "type": "BMTR_1",
                  "props": { "pressure": 42, "power": 88 },
                  "slotState": { "edge": { "edgeState": 1 } } }] } }

// 4. 之后按 tick 推增量 —— 只带变化字段，必须深合并
{ "type": "message", "clientId": "<APP>", "data": {
    "t": "ev", "ev": "slots.patch",
    "slots": [{ "slotId": "s1", "props": { "pressure": 77.5 } }] } }
```

`props.pressure` 就是气压。`slotState.edge.edgeState` 是 APP 自己的边控状态
（0 停 / 1 刺激 / 2 冷静计时 / 3 判断低于蓝线 / 4 允许高潮），本程序不依赖它，
只用 `pressure` 自己算，这样阈值完全可控。

> **注意**：`slots.patch` 是**增量**帧。直接把 `props` 覆盖上去会丢掉 `power`
> 等没变化的字段，所以 `edge_sensor.py` 里做的是逐字段 `update`。

| `relay_v4.py` | DG-LAB V4 中继服务端的纯 Python 实现 |

| `tools/mock_dglab_app.py` | 假 DG-LAB APP，没有硬件时跑通全链路 |
| `selftest.py` | 无硬件自测（协议 / 状态机 / 中继 / 联动） |

`hello` / `client_attached` / `message` 透传 / 心跳 / 空闲超时 4002 / 控制方断开
踢被控方 4000。这样目标机器只要 Python，不用装 bun。

## 4. 用法

### 4.1 图形界面（推荐）

```bash
python3 funf_edge_gui.py
```

界面分左右两栏，操作顺序就是需求里的顺序。

> **地址说明**：中继监听 `0.0.0.0`，界面上显示的是本机**局域网 IP**（如
> `ws://192.168.1.185:9998/`）。二维码编码的就是这个地址，因为手机上的
> DG-LAB APP 必须能路由过来 —— `127.0.0.1` 在手机上指向手机自己。
> 换了网络导致 IP 变化时，点地址栏右边的 **↻** 重新探测。

**① 连玩具** — 扫描 → 连接 `SOSEXY`（手机 App 必须先完全退出，它独占连接）。

- **强度滑杆拖动即下发**：不用点任何「下发」按钮。
  实现是「目标值 + 插值逼近」：拖动只更新目标，发送循环每 40ms 朝目标
  推进一步（步长自适应，差得远迈大步、接近了收小步），所以输出是连续
  过渡而不是一格一格跳。松手时补发精确终值。
- **模式下拉改变即下发**。
- **电量自动查询**：连上后立刻查一次，之后每 30 秒刷新，显示在顶栏；
  ≤40% 变黄、≤20% 变红。不需要手动点。

**② 连灵猫**

1. **程序启动就自动起中继并连上，二维码立即出现** —— 不需要先点任何按钮。
   配对区只展示**一条完整地址**（局域网 IP + tid，如
   `ws://192.168.1.185:9998/?tid=abc123`）和它对应的二维码。
   中继地址本身不单独显示 —— 用户要复制的是带 tid 的那个。
2. 打开 DG-LAB 4 APP → Socket 控制 → 扫二维码，或复制那条地址手填。
3. APP 接入后自动找到 `BMTR_1` 设备，气压开始刷。

想连官方服务器就把地址改成 `wss://trex.dungeon-lab.cn/v4`，本地中继可以不启。
地址变了（换网络 / 换 WiFi）点 **↻** 重新探测；中继想停掉点 **停止中继**；
连接断了点 **重连** 重新拿 targetId。

**③ 设阈值 → 开玩具 → 布防**

- 阈值 / 回差 / 持续 / 冷静 四个参数，改完按回车即生效。
- 手动把吮吸、震动、微电流推上去，点「下发」。
- 点 **布防（开始边控）**。之后气压一到线，程序立刻：

  1. 连发 3 次全停帧 `010100 03000111000003110000071100`
  2. 可选：先发取消失控帧（失控模式开着时设备会忽略手动帧）
  3. 滑杆归零，界面显示「已触发 · 冷静中」，**手动下发被锁定**

- 气压回落到 `阈值 - 回差` 以下，**从这一刻起**再等冷却时长，然后才
  **自动重新布防并把触发前的强度+模式重新下发** —— 回到原来的状态。
  - 冷却计时起点是「回落到阈值以下」，不是触发时刻。气压一直高着的话，
    冷却期不会空转，恢复时刻会被一直推后
  - 冷却中途气压又升回去，计时作废；再降下来要重新从零计时
  - 状态栏分阶段显示：`已触发 · 等气压回落至 40` → `冷却中 剩余 2.1s` → `监视中`
  - 触发瞬间会先快照三路设定再归零，否则没得恢复
  - 触发前输出本来就是 0 的，回落时不发帧（不会突然动起来）
  - 取消勾选「回落自动重布防」则只撤防、保持停止，不会自动恢复输出

## 5. 触发上限 → 自动撤防（最后冲刺）

勾上「触发上限后自动撤防」并设个次数，玩法就变成有限回合：

```text
第 1 次越线 → 全停 → 回落 → 冷却 3s → 恢复原强度
第 2 次越线 → 全停 → 回落 → 冷却 3s → 恢复原强度
...
第 N 次越线 → 全停 → 回落 → 冷却 3s → 撤防 + 保持输出（不再被气压打断）
```

最后那一步是**冲刺**：冷却走完就把原强度重新下发并撤防，之后气压再高也不
会停 —— 因为已经撤防了，状态机不再介入。这个「走完最后一次冷却才冲刺」的
顺序很重要：不能在触发瞬间就撤防，否则最后一次惩罚被跳过。

- 次数输入框只有勾选后才可用
- 旁边的提示会显示 `还差 N 次` / `最后一次冷却后撤防` / `已撤防 · 冲刺中`
- 取消勾选 = 不限次数（`max_trips=0`），行为回到原来的循环

## 6. 四个参数怎么调

| 参数 | 默认 | 作用 | 调法 |
|---|---|---|---|
| 阈值 | 45.0 | 越线即停 | 正常波动 0–40，45 是刚越线的位置；敏感就降到 35–40 |
| 回差 | 5.0 | 回落到 `阈值-回差` 才算「松开」 | 太小会在阈值附近疯狂开关，太大要松很久才恢复 |
| 持续 | 0.15s | 连续超阈多久才真停 | 防呼吸/体动造成的瞬时尖峰误触发；抖得厉害就加到 0.3–0.5 |
| 冷却 | 3.0s | **气压回落到 `阈值-回差` 以下之后**，还要等这么久才恢复 | 边控的「惩罚期」。注意计时起点是回落后，不是触发时 |

另外有个隐式的 **数据失效保护**：气压超过 3 秒没更新（`stale_after`），
状态机就不再做判断 —— 不会因为传感器掉线而误触发，也不会误判「已回落」。

## 7. 实现上踩到的几个坑

**`slots.patch` 是增量帧。** 直接赋值会丢字段，必须逐字段合并。

**实时下发绝不能排队历史值。** 这是手感问题的根因。早期每次变化都
`post()` 一条指令，而 `do_send` 里每帧 `sleep(0.12)` —— 用户从 0 拖到 100
再拖回 0 之后，设备还在以 120ms/格 的速度把刚才的轨迹重播一遍，听感就是
「咔咔咔」地慢半拍爬上去。

现在的做法：
1. 拖动只更新**目标值**，不产生队列项
2. 40ms 一个 tick 朝目标插值逼近，步长自适应（`|delta| > 30` 时走一半）
3. `post_live()` 合并投递 —— 队列里已有未执行的实时帧就直接替换成最新的，
   任何时刻最多只有一条待发
4. `do_send_live()` 内部不 sleep，只 `await asyncio.sleep(0)` 让出控制权
5. 松手 `_flush_now()` 一次写到位，避免停在半路

实测：快速来回拖动 2 秒，松手后 47ms 收尾（改之前是 1.9 秒的回放）。

**多行内容配大二维码要用嵌套 frame。** 右侧二维码 240px 高会撑高容器，
左侧三行若直接用 `grid` 放在同一容器里，Tk 会把多余高度平均分给各行，
表现为行间空出一大片。正确做法：左侧内容装进子 frame 用 `pack` 紧密堆叠，
该 frame 以 `sticky="nw"` 贴左上角。

**二维码颜色映射不能反。** `qrcode` 的矩阵里 `True` = **深色**模块，第一版
写成 `"#ffffff" if m[row][col]`，画出来是白底白码 —— 看着有图案，永远扫不出。
另外三个坑：静区（`border=4`）、位图不能超出画布（早期按 128px 画进 118px
画布被裁）、每个模块至少 4px（3px 时 53 模块的码解码器会失败）。

**「最后一次冷却后才撤防」的顺序不能反。** 达到触发上限时如果立刻撤防，最后
那次惩罚就被跳过了。现在是在冷却结束的分支里判断 `trip_count >= max_trips`，
先走完冷却再 `on_finish`。

**冷却期从「回落后」算，不是从「触发时」算。** 早期写成 `now - trip_time`，
气压一直高着的时候冷却期在旁边空转，一降下来立刻就恢复 —— 边控就失去了意义。
现在用 `release_since` 记录「降到回落线以下」的时刻，回升则清空重计。

**参数输入框要逐个绑事件。** 早期只给「阈值」框绑了 `<Return>`/`<FocusOut>`，
改「冷静」「回差」「持续」按回车根本没传进状态机 —— 表现就是「冷静设置不生效」。
现在四个框都绑到 `_on_param_enter`，并在 `_clamp_params` 里夹到合理区间。

**越线描红必须按连续段画。** 把所有越线点塞进一条 `create_line`，中间低于阈值的
空档会被直线跨过去，看起来就像两次触发之间连了条红线。`_over_segments()` 按
「连续高于阈值」切段，并在段首尾用线性插值精确落在阈值线上。

**dwell 不能只靠「下一条采样」判断。** 如果传感器停推，越线就永远不触发。
所以 `EdgeGuard.tick()` 被 GUI 每 120ms 调一次兜底，到期判断不依赖新数据。

**触发后滑杆归零要同帧生效。** 事件处理和 `tick()` 的顺序是
「先 drain → 再 tick → 再 drain」，否则界面会短暂显示旧滑杆值。

**气压回调在传感器线程，绘图在 GUI 线程。** `press_hist` 和 CSV writer 都要加锁，
不然绘图切片会撞上正在写入的 writer。

**失控模式会锁住手动控制。** 一旦 `0009 ≠ 0` 且 `000A ≠ 0xFFFF`，设备丢弃所有手动
强度帧。所以触发时默认先发取消帧 `010100 0200091100000b1100` 再全停。

**单帧别超过 20 字节。** 固件对长帧处理不稳，三路强度拆成三条 12 字节短帧下发。

**灵猫气压的标定**：正常呼吸/体动在 **0–40** 波动，越线一般 45 以上，所以
图表上限默认 **50**，阈值默认 **45**。阈值线因此落在图表上方约 11% 高度 ——
上方留一点空间看「越线尖峰」，下面 89% 全是波动区，曲线不会被压成一条线。

数据超过 50 时图表自动扩展上限（不会把曲线削平）；也能取消「量程自适应」
手动锁定。越线的部分会用红色粗线单独描出来，一眼可见。

**气压相关的数值统一一位小数。** 阈值、回差、实时气压、图表刻度与标注、
状态栏、CSV 全部走同一个 `fmt_p()`，配置也按一位小数取整（填 45.55 会变成
45.5，并回写到输入框）。这样「框里看到的」和「状态机实际用的」永远是同一个值。

## 8. 已知限制

- 手机 App 独占 BLE 连接，**DG-LAB APP 和 FUNF APP 不能同时开**。灵猫在 DG-LAB
  APP 里，玩具走本程序的 BLE，两者不冲突。
- 中继监听 `0.0.0.0`，界面展示和二维码用局域网 IP。手机和电脑必须在同一局域网，
  且 macOS 防火墙要放行 Python（首次启动中继时可能弹窗询问）。
- 本机连中继走 `127.0.0.1`，二维码走局域网地址 —— 两者是分开的，这样局域网
  路由即使不稳也不影响本机自己的控制链路。
- 跨公网使用需要把地址换成内网穿透域名，并把 `ws://` 改成 `wss://`。
- 气压值来自 APP 的上报 tick，采样率取决于 APP，不是传感器原始速率。快速变化
  可能被漏采，所以 `dwell` 别设得太小。
- 联动是「停 → 回落恢复原设定」的闭环，但**恢复的是触发瞬间的快照**，
  不是持续跟随。触发后你手动改的滑杆值不会在下次恢复时生效 ——
  要改就得在触发前改。
